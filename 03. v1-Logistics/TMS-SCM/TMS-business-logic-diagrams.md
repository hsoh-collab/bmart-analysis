# TMS 비즈니스 로직 이해를 위한 Mermaid 가이드

## 1. 문서의 목적과 읽는 방법

이 문서는 `TMS-business-logic-in-scope.md`를 빠르게 이해하기 위한 시각적 안내서다. 기존 비즈니스 로직의 문장·정책·검증 조건을 재작성하거나 대체하지 않는다. 각 다이어그램은 시스템 경계와 업무 순서를 보여주며, 상세 규칙·예외·승인 조건·수용 기준은 원문 해당 절을 기준으로 한다.

**범위:** CDC/DC → MFC/PPC 거점 간 보충 운송. Commerce, OMS, 고객 배송, 라이더 연계는 포함하지 않는다. MFC Operations는 현장 운영 기능을 가리키며 PPC와 동의어로 사용하지 않는다. PPC는 거점/목적지를, MFC Operations는 해당 거점에서 수행하는 운영 업무를 뜻한다.

## 2. 시스템 컨텍스트와 책임 경계

```mermaid

    WMS[WMS\n재고 원장·출고/입고·LOT]
    TMS[TMS\n운송 요청·계획·차량·ETA·운송 사건]
    MFC[MFC Operations\nPPC 수령·검수·격리·적치·현장 여력]
    BI[BI / Analytics\n원천 사건·지표·분석]
    CDC[(CDC / DC)]
    PPC[(MFC / PPC)]
    SCM -->|승인된 이관 요청| TMS
    SCM -->|공급/재고 검증 및 출고 요청| WMS
    WMS -->|실제 출발·수량·증빙| TMS
    TMS -->|ETA·지연·도착/인계 증빙| SCM
    TMS -->|도착예정·운송 정보| MFC
    MFC -->|실수령·검수·격리 결과| WMS
    WMS -->|재고 반영 결과| SCM
    WMS --- CDC
    WMS --- PPC
    MFC --- PPC
    SCM -.-> BI
    WMS -.-> BI
    TMS -.-> BI
    MFC -.-> BI
```

**읽는 법:** SCM은 무엇을 얼마나 보충할지 결정하고 요청·승인을 관리한다. WMS는 실재고와 출고/입고 원장을 소유한다. TMS는 운송을 계획·배차하고 운송 사건을 추적한다. MFC Operations는 PPC 현장의 실제 수령·검수·적치와 수용 여력을 소유한다. BI는 원천 사건을 분석하지만 운영 원장을 정정하지 않는다.

## 3. 전체 CDC→PPC 보충 흐름

```mermaid
flowchart TD
    A[동일 기준시각의 수요·재고·공급 조회]
    B[보충 필요량·실행 상한 계산]
    C[추천 결과 표시]
    D[PPC 관리자 수동 요청]
    E[CDC 공급 가능량·PPC 수용량·기한·차량 제약 검증]
    F{승인 결과}
    G[반려 또는 미충족 사유 기록]
    H[승인/부분 승인 공급 약속]
    I[WMS 적격 재고 할당·피킹·검품·상차]
    J{실제 출발 가능?}
    K[보류·실패 원인 기록 및 재검토]
    L[실제 출발 1회 확정]
    M[TMS 운송 계획·배차·운행 추적·ETA 갱신]
    N[MFC Operations 실제 수령·검수]
    O[WMS 이동 중 해소 및 PPC 정상/격리 재고 반영]
    P[수량·품질·잔량 대사]
    Q{미해결 의무 존재?}
    R[사건 조사·담당/기한 유지]
    S[사용 준비·행정 종결 각각 확인]
    A --> B --> C --> D --> E --> F
    F -- 반려 --> G
    F -- 승인/부분 승인 --> H --> I --> J
    J -- 아니오 --> K
    J -- 예 --> L --> M --> N --> O --> P --> Q
    Q -- 예 --> R --> P
    Q -- 아니오 --> S
```

**읽는 법:** 추천은 이관을 생성하지 않는다. PPC 관리자의 수동 요청과 승인 뒤에 WMS 할당·출발이 진행되고, TMS가 운송을 추적한다. 도착은 수령·검수·재고 반영과 같지 않다. 실제 수령량, 정상/격리 수량, 미수령 잔량을 각각 대사한 뒤 사용 준비와 행정 종결을 따로 확인한다.

## 6. 수량 계산의 논리

```mermaid
flowchart TD
    H["H: PPC 적격 현물"]
    I["I: 보호기간 내 유효한 기존 공급 잔량"]
    F["F: 기존 공급 계보와 중복되지 않는 신규 예상 수요"]
    SS["SS: 승인 안전재고"]

    S["목표량 S = F + SS"]
    IP["재고 포지션 IP = H + I"]
    N["필요량 N = max(0, S - IP)"]

    M["이송 배수 m 적용: 희망량 올림"]
    C["실행 상한: DC 공급, PPC 수용, 차량, 기한 제약의 최솟값"]
    R["실행 상한을 m 배수로 내림"]
    O["추천량 = 희망량과 실행 상한 중 작은 값"]
    U["미충족량 = max(0, N - 추천량)"]

    H --> IP
    I --> IP

    F --> S
    SS --> S

    S --> N
    IP --> N

    N --> M
    N --> C

    C --> R

    M --> O
    R --> O

    O --> U
```

**읽는 법:** 추천량은 필요량을 단순 올림한 값이 아니다. 실행 상한을 넘지 않도록 제약 상한을 이송 배수로 내림한 뒤 희망량과 비교한다. 배수나 필수 기준이 미등록이면 임의의 0/1/무제한 값으로 대체하지 않고 영향 계산·승인을 보류한다. 상세 공식과 예시는 SCM 상세 문서를 기준으로 한다.

## 7. 예외·복구 판단 트리

```mermaid
flowchart TD
    A[예외 또는 상태 불일치 발생]
    B{실제 출발 전인가?}
    C[취소/변경 가능 범위 확인]
    D[출고 작업·예약 해제·실물 복귀 확인 후 취소 확정]
    E[출발 후에는 원이관 취소·자동 역이관·타 PPC 전환 금지]
    F{실물은 수령됐는가?}
    G[원출발·실수령·WMS 반영을 대사]
    H[미수령 잔량은 이동 중 조사 대상으로 유지]
    I[수령품은 정상/격리로 분리]
    J{WMS 반영만 지연됐는가?}
    K[이미 수령한 물량을 I에서 제거하고 반영만 복구]
    L[실제 부족을 동일 기준시각으로 재계산]
    M[새 보충은 기존 잔량·진행 공급 확인 후 별도 수동 요청]
    A --> B
    B -- 예 --> C --> D
    B -- 아니오 --> E --> F
    F -- 예 --> G --> I --> J
    F -- 아니오 --> H --> L
    J -- 예 --> K
    J -- 아니오 --> L
    L --> M
```

**읽는 법:** 시스템 응답 실패와 실물 실행 실패를 구분한다. WMS 응답 유실은 기존 작업/출발을 조회하고 재출발하지 않는다. 수령된 격리품과 미수령 잔량은 서로 다른 수량이다. 새 요청은 기존 공급 계보와 중복되지 않도록 별도 승인한다.

## 9. 반드시 기억할 설계 원칙

- **추천 ≠ 요청 ≠ 승인 ≠ 할당 ≠ 출발 ≠ 수령 ≠ 사용 가능 ≠ 행정 종결.** 각각 독립적으로 확인한다.
- **1요청 1이관 1출발.** 부분 승인이나 부족량을 같은 요청의 두 번째 출발로 처리하지 않는다.
- 동일 공급의 승인·할당·출발은 서로 다른 공급량이 아니라 하나의 공급 계보다.
- 실제 수령량은 원출발에 연결하고 이동 중에서 한 번만 해소한다. WMS 반영 지연 때문에 중복 보충하지 않는다.
- 수령 정상량, 수령 격리량, 미수령 잔량은 분리한다. 격리품은 사용 가능 현물도 미도착 공급도 아니다.
- 출발 후 원이관 취소·자동 역이관·타 PPC 전환은 초기 범위에서 지원하지 않는다.
- 계획 ETA나 운송 완료만으로 WMS 재고 원장·MFC 검수 결과를 확정하지 않는다.
- 미설정 필수값을 0, 1 또는 무제한으로 대체하지 않는다. 영향받는 신규 계산·승인을 보류하고 담당·사유를 남긴다.
