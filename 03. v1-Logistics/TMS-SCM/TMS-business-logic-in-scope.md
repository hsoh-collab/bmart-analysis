# TMS 상세 비즈니스 로직 및 운영 기준

## 1. TMS의 정의·하위 시스템·협업 경계

TMS는 승인된 거점 간 운송 요청을 수신하여 **운송 계획, 화물·적재 단위 구성, 차량·회차 배정, 배정 변경, 경로·ETA, 운송 관제 및 실물 인계 증빙**을 관리한다. TMS의 계획·배정 성공은 실제 출발·도착·수령 또는 재고 원장 반영 완료와 다르다. 물리 재고 원장은 WMS가 DC/PPC별로 관리하며, 보충 필요와 공급 승인은 SCM / Replenishment, 현장 수령·검수·작업 여력은 MFC Operations, 분석 모델과 지표는 BI / Analytics가 각각 소유한다.

### 1.1 적용 범위와 거래·실물의 기준

TMS의 업무 범위는 **CDC/DC→MFC(PPC) 거점 간 간선 운송**이다. 승인된 이관 요청을 바탕으로 운송 편성·차량 배정·회차·경로·ETA·운행 관제·도착 및 인계 증빙을 관리한다. 간선 운송은 실제 출발·도착·하차 결과를 수집하여 WMS의 재고 반영 및 MFC Operations의 현장 수령·검수 결과와 대사한다. DC의 계획된 출고 회차를 사용하는 것과 반복 노선 최적화는 다르다.

SCM / Replenishment는 보충 필요·공급량·이관 승인, WMS는 상품·DC/PPC 재고와 실제 출발/수령에 따른 원장 반영, MFC Operations는 PPC 수령·검수·현장 여력, BI / Analytics는 분석 모델과 지표를 각각 확정한다. 관제 시스템은 운송 사고·승인·운영자 개입을 조율한다. TMS의 운송 종료가 PPC 재고 반영 완료나 보충 업무 전체 완료를 뜻하지 않는다. 외부 운송사 계약/API와 회계 정산·실제 지급 자동화는 구현 범위에서 제외한다.

명시적 팀 결정 외의 아래 운송/배차 상세는 `[설계안]`이다. 상용 제품 조사와 외부 사례의 수치를 바로픽 확정 정책으로 간주하지 않는다.

외부 공급업체→DC 실제 입고·검수/구매발주는 초기 구현에서 제외하고 승인된 DC 초기 보유부터 운영한다. CDC/DC→MFC(PPC) 보충 운송을 포함한다. 센터 간 출발 후 실제 DC 반송/역이관·타 PPC 전환은 초기 제외다.

### 1.3 다른 영역과의 협업

| 연계 영역 | 함께 정의해야 하는 업무 | 상대 영역이 소유하는 책임 |
|---|---|---|
| WMS | 출고 가능 화물·실상차·출발 증빙·도착 수량·검수 결과·재고 대사 | 상품/SKU/LOT 정본, 센터별 재고 원장, 출고·입고·이동 중 재고 반영 |
| SCM / Replenishment | 승인 이관·목적지·수량·필요 도착 시각·우선순위·지연 영향 | 보충 필요량 산정, CDC 공급량 결정, 이관 승인·변경 및 보충 이행 판단 |
| MFC Operations | 도착 예고·수령 창·현장 용량·실제 도착/인계·수령 및 검수 결과 | MFC/PPC 운영시간·작업 제한·현장 수령·검수·격리·적치 여력 |
| BI / Analytics | 원천 운송 사건·계획/실제 시각·수량 차이·비용 근거 | 분석 모델·지표 정의·집계·대시보드·데이터 품질 분석 |
| 관제 시스템 / BackOffice | 지연·사고 경보, 예외 승인, 운영자 개입과 정책 버전 | 권한·승인·운영 개입 이력, 운송사/계약/요율 및 예외 처리 정책 |

상품 정본은 WMS이며 상품/품질 승인 권한과 관제의 정책 승인 역할을 구분한다. 재고 반영은 WMS가 확정하고 현장 수령·검수 사실은 MFC Operations가 확정한다. TMS는 운송 요청·계획·배정·운행·인계 증빙을 관리하며 각 영역의 기능을 복제하지 않는다. BI / Analytics는 원천 사건과 지표 협업을 수행하되 분석 결과로 운영 원장을 직접 수정하지 않는다.

직접 조회/검증 요청, 확정 사건 수신, 이벤트 전달, 배치 대사를 구분한다. 모든 시스템을 직접 호출한다고 가정하지 않으며 같은 요청·사건의 재전송은 원결과를 조회하고 다른 내용을 같은 요청으로 덮어쓰지 않는다. 성공한 원장 반영과 실패한 통지/조회 갱신을 분리해 미완료 단계만 복구한다.

[확정 정책] 상품 식별은 E-낱개/B-독립 실물 묶음과 전역 공통 8자리 일련번호를 사용한다. DC/MFC는 같은 SKU를 쓰되 센터별 재고·예약·위치를 구분한다. 같은 기초상품의 구성 낱개 수 합산 기본 10개 제한은 고객 구매가 아닌 센터 간 보충에는 적용하지 않는다. BOX/PLT는 상품이 아닌 물류 취급 단위이며 E/B포장 전환은 초기 지원하지 않는다.

### 1.4 핵심 경계·업무 결과의 판단

TMS는 거점 간 운송 계획·화물 단위·차량 배정·ETA·운행 및 인계 증빙을 책임진다. WMS 재고 원장, SCM 보충 승인, MFC Operations의 현장 수령·검수 판정을 운송 상태로 덮어쓰지 않는다.

요청 접수·공급 승인·운송 계획·차량 배정·실제 수행·원장 반영·분석 집계는 각각 다른 결과다. 물리 수량은 센터·SKU·LOT·상태·원실물 단위로 대사하며, 운송 실적과 비용 산정 근거는 승인된 계약·정산 결과와 구분한다. 타임아웃·오프라인 기록·GPS 도착·설비 완료 신호만으로 최종 실물/거래를 확정하지 않는다. 권한·최신 버전·실제 증빙·남은 의무를 확인한 뒤 업무를 종료한다.

**운송 요청 → 중복·적격 검증 → 화물·적재 단위 구성 → 차량·회차 편성 → 차량 배정 확정 → 출고 준비·운행 조율 → 실제 운송 결과 수신 → 남은 운송 의무 대사 → 종결**로 이어진다.

계획 버전·배정 버전·계획 시각·최신 예상·실제 사건을 구분한다. 운송 요청 접수 시각과 실제 상차·출발·인계 시각을 혼동하지 않는다. 운행 종료와 실제 물품 책임 종료도 별도로 추적한다.

## 3. DC→PPC 운송 계획·차량·회차



### 3.1 수요 편성·차량

SCM 승인 이관과 WMS의 준비 화물·SKU/LOT·수량·BOX/PLT·중량/부피·온도 조건을 대조한다. 같은 물량을 여러 운송에 중복 배정하지 않는다. 승인 요청은1이관1출발이며 차량 부족을 이유로 같은 요청을 여러 출발로 나누지 않는다. 불가능하면 계획 보류·수량/회차 재승인을 요청한다. 여러 요청을 한 차량에 싣는 것은 각 목적·수량을 구분하고 적재 조건을 통과할 때만 가능하다.

상품뿐 아니라 팔레트·상자·용기 중량과 실측 부피를 포함해 차량/구획 한도를 검사한다. 차량 대수 가용성과 차량1대 적재능력은 별도다. 냉장·냉동 구획·예냉·혼적·적층·압궤·봉인·하차 접근성을 확인하고 안전 한도 초과는 출발을 차단한다. EA를 고정 상수로 팔레트 수나 톤수로 바꾸지 않는다.

차량은 가용 위치/시각·진행 운송·등록 차량 유형·적재 적합성·운행 제한을 검사한다. 가까워도 수행 중이거나 구획/적재 조건을 맞추지 못하면 제외한다. 계획되지 못한 요청은 미배정 사유를 유지하고 실패분만 대체 차량/회차로 재검토한다. 성공한 배정을 재계획 때 다시 만들지 않는다.

### 3.2 회차·시간창

DC 계획은 작업 개시06:00/11:00/16:00/21:00, 출발08:30~09:30/13:00~14:00/18:00~19:00/23:00~익일00:00다. PPC의 실제 수령 창과 검수·적치 여력이 맞는 회차만 편성한다. 일반 보충6시간·긴급2시간은 목표이며 무조건 도착을 보장하지 않는다.

부산 간선 차종3.5톤/5톤 듀얼온도 탑차,15km 이내30~40분·15~35km50~70분·35~50km80~110분은 계획 입력이다. 실측 SLA나 모든 차량의 법적 적재한도를 의미하지 않는다. DC 도크10개·일60~80대/피크12~15대 계획도 실제 체류시간과 겹침을 검증한다.

도착뿐 아니라 하차·검수·사용 준비까지 승인된 필요 도착 시점을 충족하는지 검토한다. 정차지 이동·대기·작업시간을 모두 포함하며 중간 PPC 하차가 끝났다고 전체 운송을 완료하지 않는다. 차량·화물·시간 변경은 적재/시간 제약을 재검증하고 원계획·최신예상·실제시각을 각각 보존한다.

`[팀 확인 필요]` PPC 매일 오전 수령안과 DC4회차/정상 당일 오후 공급안을 연결할 실제 시간표가 필요하다. 운송을 단순 기록만 한다는 초기 입고 정의서의 범위는 현재 요청에 따라 확장하되 외부 운송사/API가 이미 연동된 것으로 쓰지 않는다.

### 3.3 회차·수령 창·저온 대기의 실행 조건

[채택 설계] DC 작업/출발 회차, PPC 수령/검수 창, 도착 예정, 온도대별 승인 대기 한도를 함께 검사한다. 미설정·조회 불명은 해당 신규 편성/출발을 보류하고 SCM/DC/PPC 담당자에게 보완 요청한다. 이미 운송 중이면 현위치·보관 조건·누적 대기를 확인해 안전 도착/수령을 조율하며 과거 출발을 취소하지 않는다. 저온 분 단위 한도 초과/노출 불명은 품질 사건으로 전달하고 단순 회차 변경으로 이력을 초기화하지 않는다.

MFC/PPC 수령·검수 창과 DC 출발 회차는 별도 운영 설정이다. 양쪽 조건이 모두 맞을 때 운송을 편성하며, 08시/09시 원본 차이를 임의로 하나로 확정하지 않고 해당 센터·일자 승인 설정을 사용한다.

## 4. 간선 출발·운행·도착·차이

출발 전 WMS 승인·검품·실상차, 차량·운전자·목적지·봉인·적격 온도, 미취소를 확인한다. 실제 출발 증빙을 WMS와 공유하고 **WMS만 DC 현물 감소·이동 중 전환을 확정**한다. TMS가 두 번째 재고를 차감하지 않는다.

운행 중 위치·통신 최신성·온도 이력·지연 사유·변경 ETA를 기록한다. 도착은 실제 차량 도착, 하차는 실제 화물 인계, 정상 인수는 PPC 검수 합격 결과다. TMS는 하차 수량/화물·시각·담당·사진/봉인 증빙을 제공하고 MFC Operations의 검수 결과를 받는다. 마지막 정차 완료도 미해결 수량·품질 사건을 자동 닫지 않는다.

지연은 계획/필요 도착 시각과 승인된 임계값으로 판단한다. 기한 미설정을0분으로 간주하지 않는다. 후속 정차 ETA를 재계산해 SCM에 공급 유효성 재평가, MFC Operations에 인력·보관·수령 창 조정을 요청한다. 도착 예정 변경으로 과거 약속 위반을 지우지 않는다.

미도착·과도착·오인계·파손·온도 이탈·봉인 훼손은 안전 확보 → 영향 화물 식별 → DC 상차/출발·차량/정차·PPC 재계수 대사 → 책임/처분 승인 순서다. 자동 손실·정상 인수·타 PPC 재배정을 하지 않는다. 출발 후 취소·역이관·강제반송·PPC 간 전환은 초기 미지원이다. 품질상 정상 판매가 불가능하면 보관 책임과 현 위치를 남기고 관제로 상신한다.

수량 차이는3영업일 조사, 추정손실10만원 초과 본사 상신을 지원한다. 종결에는 본사 재고 책임자 또는 운영 본부장 전자 승인과 재고 주체의 대사가 필요하다. TMS 운행 종료와 사고 손실 승인·품질 폐기는 별개다.

[채택 설계] 원출발과 대사한 실제 수령량 전체는 PPC 정상/격리 현물로 귀속하고 이동 중에서 한 번 해소한다. 검수 합격량만 정상, 미판정·부적합량은 격리이며 판매 가용은0이다. 현장 수령 사실은 MFC Operations가 확정하고, 같은 결과의 PPC 정상/격리 재고 반영과 이동 중 해소는 WMS가 수행한다. 격리품 실제 폐기는 WMS가 PPC 격리에서만 차감하고 미수령 잔량은 별도 유지한다. TMS는 인계 화물·실수량·시각·인계자/인수자·위치 증빙만 제공하며 운송 종료가 재고 수령을 대신하지 않는다.

## 5. 간선 화물·수량 대사와 출발 후 사고

운송 요청의 목적지·회차·차량 구획·중량/체적·온도·BOX/PLT구성을 WMS 출고와 비교한다. BOX/PLT는 운송 취급 단위이고 SKU 수량은 하위 구성으로 대사한다. 다른 PPC 화물 상차·온도 부적합·하중/수령 창 미확인은 출발을 보류한다. BOX/PLT의 물류 취급 단위와 하위 SKU 수량을 별도로 대사한다.

실제 출발 증빙은 WMS의 DC차감/이동중 전환을 뒷받침하지만 TMS가 독립 재고를 변경하지 않는다. 도착·하차·MFC 실수령·WMS PPC 반영·판매 준비를 분리한다. 출발 48·실수령 46이면 이동 중 2를 조사하며 실제 격리 수량과 미수령 수량을 혼동하지 않는다. ETA 지연은 PPC 수령 창·품질/기한·SCM 보호기간을 재검증한다.

한 요청 한 출발과 출발 후 목적지 변경·자동 역이관/실제DC반송 초기 제외를 유지한다. 신규 자료의 경로 전환·역방향TRF는 향후 제안으로 보존하고 원운송 완료 버튼으로 실행하지 않는다. 사고 실물은 현재 위치/보관 책임을 기록하고 목적 PPC 안전 수령과 품질/차이 해결을 조율한다.

[채택 설계] DC 실제 출발 이후에는 원이관 취소·타PPC 경로 전환·자동 역이관/강제반송을 지원하지 않는다. 목적 PPC에서 실제 물량을 확인해 합격분만 정상 인수하고, 의심/부적합품은 온도를 유지한 별도 위치에 안전 보류한다. 정보 오류나 의심이 해소된 적격품만 재검수 후 인수할 수 있으며, 부적합 확정품은 본사 품질 책임자의 승인과 실제 폐기 증빙으로 처리한다. 실제 DC 반송은 초기 구현 범위에서 제외한다.

원출발·인수 실적을 지우거나 반송 의사만으로 DC 재고를 늘리지 않는다. 미해결 수량과 보관 책임·현재 위치를 유지하고, 폐기는 같은 물량을 소유한 원장에 한 번만 반영한다. 격리품 처분과 미수령 잔량은 별도 대사하며 동일 손실을 두 번 차감하지 않는다.

## 6. 센터 운영 제한과 안전 실행 조건

[채택 설계] PPC 운영 제한 정본은 MFC Operations, DC는 WMS다. TMS는 차량 가용성만 주관하고 센터 제한을 자체 해제하지 않는다. 차량 배정·상차·출발 직전에 최신 업무별 제한을 검증한다. 운영 중지 상태에서는 영향받는 신규 출발을 보류하고 위치·보관 책임·예상 도착 정보를 전달한다. 조회 불명/오래된 정상 응답으로 운송을 시작하지 않는다. 운송 중 안전 확보와 사고 조사·운송 결과 수신·후속 계획 의무는 유지한다.

## 7. 권한·연계 실패·중복·복구와 종결

운영자는 허용 센터·구간·업무의 계획/배정만 변경한다. 수동 배정·재배정·정차 순서 변경도 원요청·최신 계획·실물 인계 여부·승인·차량/시간/제한 조건을 검사한다. 재고 원장이나 실제 인계 결과를 계획 수정으로 덮어쓰지 않는다.

접수·계획·배정·변경·취소·실행 지시는 같은 원요청/원시도와 결과를 연결한다. 응답 유실은 기존 결과 조회 후 미완료 단계만 재전달한다. 다른 이관 내용으로 기존 요청을 덮어쓰거나 재시도로 새 운송을 중복 생성하지 않는다. 통지 실패와 배정 실패를 구분해 실제 성공한 배정을 취소/재생성하지 않는다.

운행 중 통신 단절 또는 역순 사건은 원운송·실제 시각·현장 인계·현재 보관 위치를 대사해 계획에 반영한다. 시스템상 상태 공백이 있어도 이미 인계한 물품을 미인계로 간주해 중복 운송하지 않는다. TMS 복구 후 미해결 요청·배정·실물/결과 불명·사고를 주관 시스템과 대사한다. 관제 조회 장애만으로 정상 운행 전체를 중단하지 않되 필수 안전/권한 검증 불가는 보류한다.

# 10. TMS와 WMS의 상세 협업·책임 경계

## 10.1 협업 목적과 원장 소유권

WMS는 상품·센터별 물리 재고의 정본이다. DC와 PPC/MFC의 재고, 예약, 로케이션, 재고 상태, 출고 차감, 이동 중 재고, 입고·격리·폐기 반영은 WMS가 소유한다. TMS는 운송 요청에 포함된 화물과 실물 인계·운행 사실을 관리하며 WMS 재고 원장을 직접 수정하지 않는다.

WMS가 소유하는 업무는 다음과 같다.

- 상품 정본과 SKU 식별, E-낱개/B-독립 실물 묶음 식별 및 공통 일련번호 관리
- DC/PPC별 재고 수량·상태·위치·LOT와 재고 원장 이력 관리
- 출고 가능 재고, 예약, 피킹·검품·패킹·출고 준비 및 출고 중지 판단
- 실제 출고에 따른 DC 재고 차감 및 이동 중 상태 전환
- PPC 실제 수령 결과에 따른 이동 중 수량 해소, PPC 정상·격리 재고 반영, 입고·폐기 원장 처리
- 재고 조정, 재고 차이 조사 결과의 원장 반영, 폐기와 손실의 단일 반영
- 재고 소유자·상태·LOT·원실물 단위의 추적과 대사

TMS가 소유하는 업무는 다음과 같다.

- 운송 요청의 접수·검증·중복 방지와 원요청 계보 유지
- 운송 대상 화물의 운행 단위 구성, 차량·구획·운송 수단 적합성 검사
- 운송 계획, 회차·정차 순서·운행 시간·ETA, 차량/운전자 배정과 재배정
- WMS 출고 준비·실상차 정보와 운송 요청의 일치 여부 확인
- 실제 출발·운행·도착·하차·인계 증빙을 수집하고 WMS 결과와 대사할 자료 제공
- 운송 중 사고·지연·온도 이탈·봉인 훼손·수량 차이의 운송 사건 기록 및 해결 조율
- 운송 실적·지연·인계 차이·비용 산정 근거를 관계 원장과 BI에 전달

TMS는 WMS가 반환한 재고 수량을 운송 계획의 편의를 위해 임의 수정하지 않는다. 운송 계획상의 예정 수량, WMS 출고 확정 수량, 실제 상차 수량, 도착지 실제 수령 수량, 검수 합격 수량, 격리 수량, 미수령 수량을 서로 다른 사실로 보존한다.

## 10.2 DC 출고 전 인터페이스

운송 요청이 생성되면 TMS는 원요청 ID, 요청 버전, 출발 DC, 목적 PPC/MFC, 필요 도착 시각, 화물 식별자, SKU/LOT, 요청 수량, 취급 단위(BOX/PLT 등), 중량·부피, 온도 조건, 봉인·취급 주의사항을 WMS 및 SCM의 승인 이관 정보와 연결한다. 실제 제공 필드는 각 시스템의 인터페이스 계약으로 확정하며, 값이 없는 필드를 임의의 0·무제한·정상으로 해석하지 않는다.

TMS는 WMS에 출고 준비 상태, 출고 가능 화물, 검품 완료 여부, 출고 중지 여부, 출고 위치/도크, 예정 상차 시간, 실상차 확정 결과를 조회하거나 이벤트로 수신한다. 이 연계는 WMS의 출고 판단을 TMS가 대체하기 위한 것이 아니다. TMS는 반환된 사실을 바탕으로 차량과 회차를 계획하고, 운송 제약이 충족되지 않으면 출발을 보류한다.

출발 전 필수 대조 항목은 다음과 같다.

- SCM 승인 이관의 목적지·요청 수량·필요 도착 시각과 WMS 출고 준비 화물의 일치 여부
- 요청 SKU/LOT와 실제 피킹·검품 대상 SKU/LOT의 일치 여부
- 요청 수량과 WMS 출고 확정 수량, 실제 상차 수량의 일치 여부
- BOX/PLT 등의 취급 단위와 그 하위 SKU 수량의 관계 및 중복 집계 여부
- 차량 총중량·구획별 적재량·부피·온도대·혼적·적층·압궤·봉인 조건
- 목적 PPC/MFC의 수령 창, 검수·적치 여력, 도크·접안 제약
- 취소·출고 중지·최신 버전 변경·품질 보류 사건의 존재 여부

필수 확인이 미완료이거나 응답이 오래되었거나 조회에 실패한 경우, 신규 출발은 보류한다. 이미 운송 중인 물량에 대해서는 출발 전 검증을 소급하여 취소하지 않고 현재 위치, 화물 상태, 보관 책임과 안전한 후속 조치를 확인한다.

## 10.3 출발·이동 중 재고 전환

TMS는 실제 출발 시각, 차량/기사, 운송·정차 식별자, 출발 증빙, 봉인 정보 및 실제 출발 화물 내역을 WMS에 전달한다. WMS는 자신이 관리하는 출고 확정 절차에 따라 DC 재고 차감과 이동 중 재고 전환을 반영한다. TMS의 출발 이벤트는 원장 반영을 위한 근거이지, TMS 자체의 재고 차감 명령이 아니다.

출발 이벤트 통지가 실패하더라도 실제 출발 사실을 새 운송으로 재생성하지 않는다. TMS는 원출발 이벤트의 고유 ID와 결과를 조회하고 통지 또는 원장 반영 확인 중 미완료 단계만 재시도한다. WMS가 이미 반영한 출발을 재수신하면 중복 차감 없이 기존 결과를 반환해야 한다.

출발48개, 목적지 정상 수령44개, 격리 수령2개, 미수령2개인 사례에서는 WMS의 이동 중 잔량과 실제 수령·격리·미수령을 구분하여 대사한다. 정상44개와 격리2개는 실제 도착한 수령 수량이며, 미수령2개는 실제 수령 수량에 포함하지 않는다. 운송 취급 단위인 BOX/PLT와 하위 SKU 수량을 동시에 더하여 물량을 중복 집계하지 않는다.

## 10.4 PPC/MFC 입고·검수·격리·폐기

도착 차량의 현장 도착, 하차 시작, 실물 인계, 실제 수령, 검수 합격, 판매 준비 가능 상태는 별도 사건이다. TMS는 실제 인계한 화물·수량·시각·인계자/인수자·위치 및 증빙을 제공한다. MFC Operations는 현장 수령·검수 결과를 확정하고, WMS는 해당 결과를 바탕으로 재고 원장을 반영한다.

- 검수 합격품: MFC Operations가 합격 사실을 확정하고 WMS가 PPC 정상 재고로 반영한다.
- 검수 미완료품: 합격으로 간주하지 않는다. 현물 위치·보관 책임·미판정 상태를 유지하고 판매 가용으로 전환하지 않는다.
- 부적합·의심품: MFC Operations가 격리 위치와 품질 사유를 기록하고 WMS가 격리 재고로 반영한다. 판매 가용 수량은 0으로 취급한다.
- 미수령 수량: 실제 인수 사실이 없는 잔량으로 유지하며, 실제 도착 또는 정상 인수로 자동 처리하지 않는다.
- 폐기: 필요한 품질/운영 승인과 실제 폐기 증빙을 확보한 후 WMS가 해당 격리 재고에서 한 번만 차감한다. TMS 운행 종료만으로 폐기를 확정하지 않는다.
- 재검수: 정보 오류 또는 의심이 해소된 적격품은 MFC Operations가 재검수 결과를 확정하고 WMS가 승인된 결과를 반영한다.

TMS는 검수 판정이나 재고 상태를 자체 결정하지 않는다. 운송 사건이 해결되지 않은 상태에서 운송의 물리적 이동이 끝났더라도 수량 차이·품질 조사·손실 승인 의무는 별도로 열린 상태로 유지한다.

## 10.5 WMS 연계 실패·대사 규칙

WMS 인터페이스는 요청/이벤트의 고유 식별자, 원운송/원출발 ID, 센터, SKU/LOT, 수량, 상태, 발생 시각, 수신 시각, 버전 및 처리 결과를 상호 추적할 수 있어야 한다. 실제 스키마는 API/이벤트 계약에서 확정하되, 업무상 필요한 추적성을 제거해서는 안 된다.

- 요청 타임아웃은 실패 확정이 아니다. 먼저 동일 키의 기존 처리 결과를 조회한다.
- 같은 출발·수령·격리·폐기 사건의 재전송은 중복 원장 반영을 만들지 않는다.
- TMS의 예정 수량과 WMS의 원장 수량이 다르면 어느 한쪽을 자동 덮어쓰지 않고 차이 사건을 만든다.
- 수량 차이에는 원출발, 실제 상차, 실제 인계, MFC 실수령, 검수 합격/격리, WMS 반영 결과를 연결한다.
- WMS 반영 성공과 BI 통지 실패, 또는 WMS 반영 성공과 TMS 화면 갱신 실패를 분리하여 실패한 통지·조회 갱신만 복구한다.
- 미수령 잔량, 격리 현물, 이동 중 원장 잔량을 별개로 대사하고 같은 손실을 두 번 차감하지 않는다.
- 재고 조정·손실 승인·폐기는 권한 있는 재고 소유자와 승인자가 확정하며 TMS 운영자가 운송 상태 변경으로 이를 대신하지 않는다.

# 11. TMS와 SCM / Replenishment의 상세 협업·책임 경계

## 11.1 SCM의 결정과 TMS의 실행 책임

SCM / Replenishment는 공급 필요를 계산하고 어떤 상품을 어느 거점에 얼마나, 언제까지 공급할지 결정하는 영역이다. 이 문서의 거점 보충 시나리오에서는 MFC/PPC가 CDC에 필요한 수량을 발주하거나 보충 요청을 생성하고, SCM / Replenishment가 해당 수요를 검토하여 공급 계획과 이관 승인을 확정한다. TMS는 보충 필요량을 새로 산정하거나 거점별 재고 정책을 소유하지 않는다. TMS는 승인된 물량을 실제로 운송할 수 있도록 계획·배차·운행·인계하고, 실행 결과와 지연·차이를 SCM에 되돌려준다.

SCM / Replenishment가 소유하는 업무는 다음과 같다.

- MFC/PPC별 필요 상품·수량·필요 시점 및 보충 우선순위 결정
- 재고 정책·수요·보호기간·공급 제약을 고려한 보충 제안
- CDC/DC에서 어느 MFC/PPC로 얼마를 공급할지 결정하고 이관을 승인
- 공급 계획의 버전 관리, 변경·취소·우선순위 변경의 업무상 승인
- 운송 지연이나 수령 차이가 보충 적정성·공급 가능성에 미치는 영향 재평가
- 공급 이행률, 부족 위험, 보충 계획 대비 실적에 대한 업무 판단

TMS가 소유하는 업무는 다음과 같다.

- SCM의 승인된 이관 요청을 운송 요청으로 접수하고 중복 여부·버전을 검증
- 요청 목적지·물량·필요 도착시간에 맞는 회차·차량·구획·운행 계획 수립
- 차량 가용성, 적재 한도, 온도대, 센터 수령 창 및 도크 제약을 반영한 실행 가능성 판정
- 배차·출발·운행·도착·실물 인계 결과 및 지연 사유 추적
- 운송이 계획을 지키지 못할 경우 영향·최신 ETA·미해결 물량을 SCM에 전달
- 완료·부분 수령·미수령·사고·품질 보류를 원요청과 연결하여 실행 실적 제공

WMS는 물리 재고 원장과 출고/입고 반영을, MFC Operations는 현장 수령·검수·작업 여력을 소유한다. SCM이 승인했다고 해서 WMS의 출고 가능 여부나 PPC의 실제 수령 가능성이 자동 확정되는 것은 아니다. TMS의 운송 계획 수립 또한 SCM의 보충 승인이나 WMS의 재고 반영을 대신하지 않는다.

## 11.2 MFC/PPC에서 CDC로 필요한 수량을 요청하는 흐름

기본 협업 흐름은 다음과 같다.

1. MFC/PPC 운영·재고 정보에서 필요한 상품과 수량, 필요한 시점이 식별된다. 해당 필요량의 산출과 현장 필요 정보의 정본은 SCM / Replenishment의 정책 및 관련 재고/현장 원천에 따른다.
2. SCM / Replenishment가 필요량·공급 가능성·보충 우선순위를 검토하고 CDC/DC에서 공급할 상품·수량·목적지·필요 도착시간을 승인한다.
3. SCM은 승인 이관 ID, 요청 버전, 출발 CDC/DC, 목적 MFC/PPC, SKU/LOT 또는 허용된 상품 식별, 수량, 필요 도착 시각, 우선순위, 취소/변경 상태를 TMS와 WMS가 사용할 수 있도록 제공한다. 실제 필드 및 전달 방식은 인터페이스 계약에서 확정한다.
4. TMS는 승인 이관 요청을 운송 요청으로 접수하고 동일 이관의 중복 접수, 버전 역전, 목적지/시간/물량 누락을 검사한다.
5. WMS는 해당 센터의 출고 가능 재고·예약·피킹·검품·실상차를 처리한다. TMS는 WMS 출고 준비 결과를 받아 운송 회차와 차량 계획을 확정한다.
6. TMS는 차량·구획·적재량·온도·센터 운영시간·PPC 수령 창을 확인하고 배차·운행을 수행한다. 계획을 충족하지 못하면 임의로 물량을 줄이거나 다른 PPC로 보내지 않고 미배정/보류 사유를 SCM에 제공한다.
7. TMS는 실제 출발·예상 도착 변경·지연·사고·도착·하차·인계 결과를 SCM에 전달한다. WMS에는 재고 원장 반영에 필요한 출발·수량·인계 증빙을 제공한다.
8. MFC Operations가 실제 수령·검수·격리 결과를 확정하고 WMS가 재고를 반영한다. SCM은 승인 물량 대비 출발·수령·합격·격리·미수령 실적을 바탕으로 보충 이행 및 부족 위험을 재평가한다.
9. 물량 차이·품질 사건·미수령 잔량이 남으면 TMS의 운송 실행이 끝났더라도 관련 업무 의무를 유지한다. SCM은 공급 대안을 판단할 수 있지만, 원운송을 지우거나 TMS에 중복 신규 이관을 자동 생성하지 않는다.

이 흐름에서 “MFC가 CDC에게 필요한 만큼 발주”한다는 업무 표현은 보충 수요가 MFC/PPC에서 발생한다는 뜻이다. 공급량·출고 가능성·실제 재고 반영·운송 실행은 각각 SCM, WMS, TMS의 책임 경계에 따라 확정한다. 발주와 운송 요청을 같은 객체로 취급하지 않는다.

## 11.3 요청·승인·운송 계획의 상태 분리

SCM의 보충 제안, 승인 이관, WMS 출고 준비, TMS 운송 계획, 실제 출발, PPC 수령, WMS 입고 반영은 서로 다른 상태와 사건이다. 각 상태의 정본은 해당 소유 시스템에 둔다.

- 보충 제안: SCM의 계획 상태이며 TMS의 출발 권한을 주지 않는다.
- 승인 이관: SCM이 공급 업무를 승인한 상태이며, WMS의 실제 출고 가능성을 보장하지 않는다.
- 출고 준비: WMS가 피킹·검품·실상차 준비를 진행하는 상태다.
- 운송 계획/배정: TMS가 실행 가능한 차량·회차·운송안을 구성한 상태이며, 실물 인계를 의미하지 않는다.
- 실제 출발: TMS가 출발 사실을 증빙하고 WMS가 원장 반영을 수행하는 단계다.
- 실제 도착/인계: TMS의 운송·인계 증빙과 MFC Operations의 현장 사실을 구분한다.
- 수령·검수: MFC Operations가 현장 수령과 검수 결과를 확정한다.
- 재고 반영: WMS가 정상/격리/미수령 등의 결과를 재고 원장에 반영한다.
- 보충 이행 판단: SCM이 승인량과 실행·수령 결과를 비교해 확정한다.

상위 시스템의 승인 상태가 하위 시스템의 실제 수행 결과를 대체하지 않으며, 하위 시스템의 성공 응답이 상위 업무의 전체 완료를 자동으로 의미하지 않는다.

## 11.4 변경·취소·부족·지연 협업

SCM이 이관 수량·목적지·필요 도착시간을 변경하거나 취소하면 TMS는 해당 요청 버전과 현재 운송 단계, WMS 출고 상태, 실제 인계 여부를 확인한다. 미출발 상태의 변경은 승인된 새 버전을 기준으로 재계획할 수 있지만, 기존 배정·제안은 구버전으로 표시하고 늦은 수락이나 구버전 실행을 차단한다.

실제 출발 후에는 초기 구현 범위에서 원이관 취소, 타 PPC 목적지 전환, 자동 역이관, 강제 반송을 실행하지 않는다. SCM이 공급 필요를 재평가하더라도 진행 중인 실물의 위치·보관 책임·안전 조치를 먼저 유지한다. 이후 별도 승인과 지원 기능이 마련되기 전까지 다른 목적지로 보내는 결정을 TMS가 자동 실행하지 않는다.

TMS는 지연 또는 차량 부족으로 필요 도착시간을 지키기 어려울 경우 최신 ETA, 지연 사유, 영향을 받는 이관·물량, 다음 조치 담당을 SCM에 제공한다. SCM은 부족 위험과 공급 대안을 판단하고, PPC 수령 창이나 인력/적치 여력은 MFC Operations가 판단한다. TMS는 SCM이 승인한 필요 도착 시각을 임의로 변경하지 않는다.

## 11.5 SCM 연계 실패·중복 방지

- SCM 승인 이관은 고유 이관 ID와 버전을 통해 추적한다.
- 동일 이관·동일 버전의 재전송은 새 운송을 생성하지 않고 기존 운송 계보와 처리 결과를 반환한다.
- 내용이 달라졌으나 동일 식별자를 가진 요청은 덮어쓰지 않고 충돌로 처리하여 상위 시스템의 정정 또는 새 버전을 요청한다.
- 취소 이벤트가 늦게 도착하면 실제 출발·인계 사건과 시간 순서를 대사하고 실물 이동을 과거로 되돌리지 않는다.
- SCM 통지 실패와 TMS 운송 생성 실패를 구분한다. 운송 생성이 성공했으면 알림 재시도로 새 운송을 만들지 않는다.
- WMS 출고 불가·PPC 수령 불가·차량 부족은 서로 다른 보류 사유로 기록하고 담당 시스템에 각각 전달한다.
- 부분 수령 또는 미수령이 발생해도 원이관의 실행 실적을 보존한다. 부족분에 대한 추가 공급은 SCM이 별도 판단·승인해야 하며 TMS가 임의로 신규 이관을 만들지 않는다.

# 12. TMS와 MFC Operations(PPC)의 상세 협업·책임 경계

## 12.1 용어와 책임 원칙

이 문서에서는 MFC Operations와 PPC Operations를 동일한 현장 운영 영역을 가리키는 용어로 취급한다. 현재 문서의 영역명은 MFC로 통일하되, 기존 업무·데이터에서 PPC라고 표기된 경우 같은 운영 거점을 의미하는지 식별 가능해야 한다. MFC Operations는 센터의 작업 가능 상태, 입고 수령 창, 검수·적치 여력, 도착 화물의 현장 수령과 검수 사실을 소유한다.

MFC Operations가 소유하는 업무는 다음과 같다.

- 센터 운영시간, 작업 중지, 안전 제한, 도크/접안, 수령 가능 시간창 및 현장 처리 용량 관리
- DC 보충 화물의 도착 예고 수신, 하차·수령 담당 및 인력/공간 준비
- 실제 도착 화물의 현장 수령 수량, 인계자·인수자, 수령 시각과 증빙 확인
- 검수 합격·미판정·부적합·격리 판정 및 현물의 위치·보관 책임 관리
- 실제 현장 작업 결과와 수령/인계 사실을 관련 원장 및 TMS에 제공

TMS가 소유하는 업무는 다음과 같다.

- MFC가 제공하는 수령 가능 시간·준비 예상·현장 제한을 운송 계획 및 배차에 반영
- DC→MFC 간선 차량·회차·도착 예정시간·정차 계획·운행 관제
- 센터 도착 예고, 지연, 차량 도착, 하차·인계 예상 및 운송 사건을 현장에 전달
- 현장 수령 차이·상차/하차 지연·인계 불명 시 현재 운송 상태와 책임 소재를 유지하고 해결을 조율

TMS는 MFC의 운영 제한을 자체 해제하지 않으며, 센터가 수령 가능하다고 응답했다고 실제 검수 합격이나 재고 반영이 확정된 것으로 처리하지 않는다. MFC Operations도 차량 배정이나 운송 완료 상태를 대신 확정하지 않는다.

## 12.2 DC→MFC 간선 도착 예고와 수령 협업

TMS는 승인된 이관 요청을 바탕으로 계획 회차·차량·목적지·화물·예상 도착시간을 MFC Operations에 전달한다. 운행 중 위치·지연·온도 이탈·사고로 ETA가 바뀌면 이전 계획 시각을 지우지 않고 최신 예상과 변경 사유를 함께 제공한다. MFC Operations는 해당 도착 예고를 근거로 수령 인력·도크·검수·적치 여력을 조정한다.

도착 예고에는 가능한 범위에서 다음 정보를 포함한다.

- 원이관 ID·운송 요청 ID·운행 ID·정차 ID와 계획 버전
- 출발 DC, 목적 MFC/PPC, 화물 식별자, SKU/LOT 및 요청 수량
- BOX/PLT 등 취급 단위, 하위 SKU 수량, 중량·부피와 온도 조건
- 계획 회차, 예정 출발/도착 시각, 최신 ETA, 지연 사유와 데이터 최신성
- 차량 식별, 운전자/담당자 식별, 봉인 정보와 취급 주의사항
- 수량 차이·품질·사고 등 현장 준비에 영향을 주는 미해결 사건

MFC Operations는 수령 창 미설정, 운영 중지, 도크 혼잡, 인력 부족, 온도대별 수용 불가 등을 반환할 수 있다. TMS는 해당 결과를 계획에 반영하고 신규 출발을 보류하거나 승인된 회차로 재계획한다. 이미 출발한 화물은 현 위치·온도 유지·누적 대기·안전 수령 방안을 조율하며, 단순히 수령 창이 맞지 않는다는 이유로 자동 반송하거나 목적지를 바꾸지 않는다.

## 12.3 실제 도착·하차·수령·검수의 분리

TMS와 MFC Operations는 다음 사건을 별도로 유지한다.

1. 차량이 센터에 도착한 사실
2. 접안·하차가 시작된 사실
3. 특정 화물·수량이 차량에서 현장으로 실제 인계된 사실
4. MFC Operations가 실수령 수량과 현물 위치를 확인한 사실
5. 검수 합격·미판정·부적합/격리 결과
6. WMS가 정상·격리·미수령·이동 중 수량을 원장에 반영한 사실
7. 공급 이관의 실행 실적을 SCM이 확인한 사실

차량 GPS가 센터 좌표에 도달하거나 운전자가 도착 버튼을 눌렀다는 이유만으로 3~7단계를 자동 완료하지 않는다. TMS는 운송·인계 증빙을 유지하고, MFC Operations는 현장 실수령·검수 사실을 확정하며, WMS는 재고 원장을 반영한다.

계획 수량과 실수령 수량이 다르면 MFC Operations가 실제 수량과 현물 상태를 확인하고, TMS는 원출발·상차·운송·정차·인계 증빙을 제공한다. WMS는 재고 원장 대사를 수행하고 SCM은 공급 이행에 미치는 영향을 판단한다. 차이가 해결되기 전까지 미수령 잔량과 격리 현물은 서로 다른 상태로 유지한다.

## 12.4 운영 시간·현장 제한·수령 용량

MFC Operations는 PPC 운영 제한 정본이다. TMS는 차량 배정·상차·간선 출발 직전에 관련 제한의 최신 버전을 검증한다. 단순 접수 중지, 신규 출발 중지, 안전상 인계 중지, 수령 창 종료, 도크/검수 용량 부족은 각각 구분해야 한다. 하나의 제한을 다른 제한과 같은 의미로 해석하지 않는다.

조회가 실패하거나 응답이 오래되었거나 제한 상태를 알 수 없으면 신규 운송 실행에 필요한 검증을 보류한다. 이미 운송 중인 경우 안전 확보와 현재 물품 책임은 유지하며, 현장에 예상 도착·위치·온도·대기 상태를 전달한다. 재개 이벤트가 도착해도 최신 제한 버전과 순서를 확인하여 과거 제한/정상 이벤트로 현재 상태를 덮어쓰지 않는다.

거점 간 운송은 DC 출발 회차, MFC 수령 창, 차량 가용성 및 센터 운영 제한이 모두 충족될 때 실행한다. 08시/09시의 실제 개시시각 충돌은 임의로 통일하지 않고 센터·일자별 승인 설정을 사용한다.

## 12.5 MFC Operations와 TMS의 인터페이스 책임표

| 업무/데이터 | MFC Operations 소유·확정 | TMS 소유·확정 | 협업·대사 규칙 |
|---|---|---|---|

# 13. TMS와 BI / Analytics의 상세 협업·책임 경계

## 13.1 BI / Analytics의 역할과 데이터 소유 원칙

BI / Analytics는 운영 시스템의 사실을 대체하는 업무 원장이 아니라, 원천 시스템이 확정한 사건·상태·수량·시각·비용 근거를 수집하여 통계·성과 분석·운영 의사결정을 지원하는 영역이다. TMS는 운송 계획·배정·운행·ETA·운송 사건·실제 인계와 운송 실적의 원천 사실을 제공한다. BI / Analytics는 이를 WMS·SCM·MFC Operations의 사실과 연결해 분석한다.

TMS가 소유하는 분석 원천 사실은 다음과 같다.

- 운송 요청·요청 버전·접수 결과·중복 차단 결과
- 계획된 회차·차량·운행·정차 순서·계획 출발/도착 시각
- 배차 후보·제안·수락/거절·타임아웃·배정·재배정 이력
- 계획 ETA, 최신 ETA, 실제 출발·도착·하차·인계 시각
- 지연·사고·온도 이탈·봉인 훼손·경로 이탈·통신 단절 등 운송 사건
- 운송 요청 수량·계획 화물·실상차·실제 인계 수량 및 미해결 차이의 연결 정보
- 운송 거리·대기·회차·추가 작업·취소·재배차 등 등록된 운송 비용 산정 근거
- 운송 실행 상태, 완료·부분 완료·미완료·미해결 의무 및 원천 갱신 시각

BI / Analytics가 소유하는 업무는 다음과 같다.

- 다중 원천 데이터를 결합한 분석 모델, 집계·차원·지표 정의 및 보고서
- 정시 출발/도착률, 운송시간, ETA 정확도, 배차 성공률, 적재율, 지연·사고율, 인수 차이율 및 운송 원가 분석
- SCM 보충 계획 대비 운송 실행·수령 실적을 분석할 수 있는 지표 구성
- 센터·회차·차량 유형·운송 구간·기간·사고 유형별 성과 분석
- 데이터 품질 문제·원천 사건 누락·지연 수집·상태 불일치의 탐지 및 원천 담당자 피드백
- 분석 정의서, 지표 버전, 데이터 갱신 시각, 출처 및 해석상 제한 표시

BI / Analytics는 TMS의 실시간 배차를 직접 확정하거나 WMS 재고를 수정하거나 SCM 보충 승인을 대신하지 않는다. 분석 결과가 운영 정책 변경에 사용되려면 해당 정책 소유자와 승인 절차를 거쳐야 한다.

## 13.2 데이터 교환과 원천 사건

TMS는 운송 요청 ID, 원이관/원주문 참조, 운행 ID, 정차 ID, 배정 버전, 사건 ID, 센터·운송 구간, 계획/실제 시각, 수량 및 상태를 이용해 원천 사건을 BI에 제공한다. 실제 이벤트 스키마와 전달 주기, 보존 기간, 개인정보 마스킹 기준은 데이터 계약에서 확정한다. BI가 요구하는 집계 편의만을 위해 원천 식별자·사건 순서·계획과 실제의 구분을 제거하지 않는다.

가능한 데이터 교환 원칙은 다음과 같다.

- 원천 사건의 고유 ID와 원천 시스템·발생 시각·수집 시각·버전을 보존한다.
- 계획값, 당시 확정 배정값, 최신 예상값, 실제 사건값을 구분한다.
- 지표 계산 시 사용하는 분모·분자·제외 기준·시간대·데이터 지연 처리 기준을 명시한다.
- 취소·재배정·부분 완료·수량 차이·사후 정정은 원래 사실을 삭제하지 않고 연결 사건으로 제공한다.
- 원천 갱신 지연 또는 수집 실패를 0건·정상·완료로 간주하지 않고 데이터 신선도/품질 상태로 표시한다.
- TMS 운송 완료, MFC 실수령, WMS 재고 반영, SCM 보충 이행을 별도 사건으로 제공하여 BI에서 임의로 동일 상태로 합치지 않도록 한다.
- 동일 이벤트 재전송은 분석 적재에서 중복 집계를 일으키지 않도록 원천 사건 ID 기준으로 식별한다.

## 13.3 지표의 의미와 책임

| 지표/분석 영역 | TMS가 제공하는 원천 | 관계 영역의 원천 | BI / Analytics 책임 및 주의사항 |
|---|---|---|---|
| 차량 배정 성공률 | 유효 운송 요청, 확정 차량 배정, 미배정 사유 | 차량 가용성·운영 제한 | 성공 정의·분모·취소 제외 기준을 문서화 |
| 정시 출발률 | 계획 출발 시각, 실제 출발 시각, 지연 사유 | WMS 출고 준비/실상차 시각 | 출고 준비 지연과 운송 출발 지연을 구분 |
| 정시 도착률 | 계획/최신 ETA, 실제 차량 도착·인계 시각 | MFC 수령 창·현장 수령 시각 | 도착과 인수 완료의 기준 시각을 구분 |
| ETA 정확도 | 시점별 ETA 스냅샷과 실제 도착 | 차량 위치·운행 사건, MFC 수령 창 | 사후 최신 ETA만으로 과거 예측 오차를 덮지 않음 |
| 운송시간 | 실제 출발·도착·정차·대기 사건 | WMS 상차 준비, MFC 하차/검수 시각 | 운송 주행시간과 현장 체류시간을 분리 |
| 적재율 | 차량 용량, 실제 적재 중량·부피·취급 단위 | WMS 실상차 SKU/LOT/BOX/PLT | 단위·분모 정의 및 상위/하위 포장 중복 방지 |
| 수량 차이율 | 계획·상차·인계 수량과 원운송 연결 | MFC 실수령/검수, WMS 원장 | 미수령·격리·정상 수령을 각각 구분 |
| 보충 이행률 | 운송 출발·도착·인계·미완료 결과 | SCM 승인량, MFC 수령, WMS 반영 | 승인 이관량과 실제 수령/합격량의 의미 분리 |
| 사고·온도 이탈 | 운송 사건, 차량·구간·시간·증빙 | 현장 품질/격리 결과 | 사고 발생과 품질 처분 결과를 분리 |
| 운송 원가 | 거리·대기·회차·추가 작업·취소 등 근거 | 승인된 계약/요율 및 회계 데이터 | TMS 근거 데이터와 승인 운임/실제 지급 구분 |

지표 이름이 같더라도 정의·시간 기준·분모·예외 처리가 다르면 서로 다른 값이 된다. BI / Analytics는 정의서를 관리하고, TMS는 원천 사건의 정확성과 재현 가능성을 유지한다. 운임 계약, 실제 회계 전표, 송금 결과가 TMS에 연결되어 있지 않다면 운송 근거만으로 확정 비용이나 지급 완료를 표시하지 않는다.

## 13.4 정정·지연 이벤트·데이터 품질

운송 완료 뒤 도착 이벤트가 늦게 들어오거나 오프라인 수행 결과가 뒤늦게 동기화될 수 있다. TMS는 원래 발생 시각과 수신 시각, 배정 버전, 실제 인계 사실을 유지하며 BI는 이를 사용해 사건 순서를 재구성하되 늦게 수신된 이벤트를 새 운송으로 집계하지 않는다.

사후 정정은 기존 기록 삭제보다 원본 사건과 정정 사건의 연결을 원칙으로 한다. BI 지표가 이미 산출된 기간에 정정이 반영되면 해당 데이터셋/지표 버전과 갱신 시각을 추적할 수 있어야 한다. 원천 사건이 누락되었거나 센터별 시간대·단위·식별자가 불일치하면 임의 보정하지 않고 데이터 품질 이슈로 등록하여 원천 담당자와 해결한다.

운전자 식별 정보와 위치 정보는 분석 목적에 필요한 최소 범위로 제공하고 권한·보존·마스킹 정책을 적용한다. BI에 전달된 집계 데이터만으로 운영 원장 사건을 직접 수정하는 기능을 두지 않는다.

## 14.2 교차 영역 사건의 소유권

- 운송 지연: TMS가 지연·ETA·운송 영향 사실을 소유한다. SCM은 보충 영향과 공급 대안을 판단하고, MFC Operations는 수령 인력·창을 조정한다.
- 출고 수량 불일치: WMS가 출고·재고 사실을 소유하고, TMS는 실제 상차·운송·인계 증빙을 제공하며, SCM은 보충 계획 영향과 부족 대응을 판단한다.
- 도착지 수량 불일치: MFC Operations가 현장 실수령 사실을 확정하고, WMS가 재고 원장을 대사하며, TMS가 원출발·상차·정차·인계 계보를 제공한다.
- 품질/온도 사고: TMS가 운송 중 발생 사건·시간·위치·차량 정보를 제공하고, MFC Operations/품질 책임자가 현물 안전 보관과 검사·처분을 판단하며, WMS가 승인된 재고 상태/폐기를 반영한다.
- 차량 배정 실패: TMS가 차량 적합성·배정 실패 사유를 소유한다. MFC Operations는 수령 여력을 제공하고, SCM은 보충 우선순위와 공급 영향 판단을 수행한다.
- 보충 부족: SCM이 추가 공급 필요·수량·승인을 소유한다. TMS는 승인된 신규 이관을 별도 운송으로 계획하고, WMS는 추가 출고·수령 원장을 반영한다.
- KPI 이상: BI / Analytics가 분석 결과·데이터 품질 문제를 소유하고 원천 사실은 TMS/WMS/SCM/MFC Operations가 각각 유지한다. BI 수치만으로 원천 상태를 변경하지 않는다.

## 14.3 필수 공통 식별자와 데이터 계보

시스템 간 상호 추적을 위해 가능한 범위에서 다음 식별자를 연결한다. 실제 필드명과 필수 여부는 인터페이스 계약에서 확정하되, 원요청에서 실물 결과와 분석 지표까지 연결되는 계보는 유지해야 한다.

- SCM 승인 이관 ID 및 이관 버전
- TMS 운송 요청 ID, 운행 ID, 정차 ID, 계획 버전 및 배정 버전
- WMS 출고/이동 중/입고 처리 참조 ID, SKU·LOT·센터·재고 상태
- MFC Operations의 현장 작업·수령·검수·격리 사건 ID
- 실제 화물/취급 단위 식별자와 하위 SKU 수량 관계
- 사건 ID, 원천 시스템, 발생 시각, 수신 시각, 정정/취소 관계
- BI 데이터셋/지표 버전과 원천 데이터 갱신 시각

이 식별자 목록은 모든 시스템이 동일한 데이터베이스를 공유해야 한다는 뜻이 아니다. 각 시스템의 정본을 유지하면서 참조 ID와 사건 계보를 통해 업무 간 결과를 연결한다.

## 14.4 공통 비기능·복구 원칙

1. 요청·이벤트의 중복 수신은 새 운송·새 출발·새 수령·새 재고 차감·새 분석 건을 생성하지 않아야 한다.
2. 타임아웃은 실패 확정이 아니므로 동일 요청의 처리 결과를 조회한 뒤 미완료 단계만 복구한다.
3. 발생 시각과 수신 시각을 구분하고 지연·역순 이벤트를 수용하되 이미 확정된 원천 사실을 조용히 덮어쓰지 않는다.
4. 원천 업무의 성공과 후속 통지·조회·분석 적재의 성공을 분리한다. 원천 성공을 되돌리지 않고 실패한 후속 단계만 재처리한다.
5. 미설정·조회 불명·오래된 상태를 0, 무제한, 정상, 완료로 간주하지 않는다. 신규 실행에 필요한 안전·권한·수량 조건이 불명확하면 보류한다.
6. 운송 상태, 실물 책임, 재고 원장, 보충 이행, 주문 이행, 품질 처분, 비용 승인, 분석 지표는 서로 다른 완료 조건을 가진다.
7. 운영자 수동 조치도 원요청·현재 버전·실물 인계 여부·권한·승인·증빙을 남겨야 한다.
8. 영역 간 직접 호출은 필수 전제로 두지 않는다. 조회 API, 이벤트, 배치 대사 또는 상위 시스템을 통한 간접 조율 중 실제 연계 방식은 구현 계약에서 정하되 책임 경계는 유지한다.

## 15.2 운송 요청·운행·실물 인계의 관계

운송 요청은 “어떤 물품을 어느 거점으로 언제까지 옮겨야 하는가”를 표현한다. 운행은 “어떤 차량·경로가 실제로 이동하는가”를 표현한다. 인계는 “어떤 물품을 얼마만큼 어느 거점의 누구에게 넘겼는가”를 표현한다. 이 세 가지를 같은 객체나 단일 완료 상태로 축약하지 않는다.

하나의 운송 요청은 여러 취급 단위로 구성될 수 있고, 하나의 운행은 여러 승인 이관 요청을 묶거나 여러 거점을 방문할 수 있다. 요청과 운행의 관계를 단순히 일대일로 고정하지 않는다. 다만 현재 DC→PPC 이관 정책의 “승인 요청 1건은 1이관 1출발” 제약은 해당 범위에서 유지한다. 일반적인 관계 모델의 유연성이 이 정책을 우회하는 근거가 되지 않는다.

센터 간 운송에서는 BOX/PLT와 하위 SKU/수량을 구분해 취급하며, 센터 간 BOX/PLT 적재 기준과 간선 화물의 분할 출발 정책은 별도 승인된 물류 규칙으로 판단한다.

## 15.3 일반 운송 생명주기와 완료 조건

일반 운송 흐름은 운송 요청 → 계획·적재 구성 → 배차 확정 → 출발지 도착 → 상차·인수 → 출발 → 운송 → 도착·하차 → 도착지 인계 → 실적·비용 근거 확정 순서다. 단계별 사실은 별도 보존한다.

- 운송 요청 접수는 운송을 실행할 의무가 생성되었다는 의미이지 배정 성공이나 출발이 아니다.
- 계획·적재 구성은 제약을 검증한 계획이며 실제 상차 사실이 아니다.
- 차량 배정 확정은 운행에 사용할 차량과 회차가 지정되었다는 의미이지 실물 인계나 운송 완료가 아니다.
- 차량 도착은 출발지/도착지의 위치 사건이며 상차·하차·수령 완료를 의미하지 않는다.
- 상차·인수는 실제 물품 책임이 바뀌는 사건으로, 물품·수량·담당자·시각·증빙을 연결해야 한다.
- 운행 완료는 이동 실행 결과이며 재고 원장 반영·검수·품질 처분·보충 이행 완료를 자동 의미하지 않는다.
- 실적·비용 근거는 수행 사실에 기반해 제공하되 승인된 계약 요율·비용·지급 결과가 없는 경우 확정 정산이나 실제 지급으로 표시하지 않는다.

## 15.4 운송 범위와 다른 업무 영역

| 영역 | 해당 영역이 소유하는 결정·사실 | TMS와의 접점 |
|---|---|---|
| SCM / Replenishment | 어떤 상품을 어느 거점에 얼마나, 언제까지 공급할지 결정 | 승인 이관과 필요 도착시간을 받아 운송 계획·실행, 실적·지연 반환 |
| WMS | 운송할 물품 출고 준비, 출고·도착 입고에 따른 재고 관리 | 출고 가능/실상차·출발 증빙·실수령 대사·원장 반영 확인 |
| TMS | 어떤 차량·운송 수단·경로로 운반할지 결정하고 운송·인계를 수행 | 운송 계획·배차·ETA·운행·운송 증빙·사건·실적 |
| MFC Operations | 도착 물품을 받을 현장 여력과 하차·인수·검수·후속 작업 관리 | 수령 창·도착 예고·현장 인계·검수/격리 결과 연계 |
| BI / Analytics | 원천 사건을 결합한 분석·지표·성과 보고 | TMS 원천 운송 사건과 비용 근거 제공 |
| 관제 시스템 | 승인·권한·운영자 개입 이력 및 운영 조율 | 배차 실패·지연·사고 경보와 운영 개입 결과 연결 |
| BackOffice | 운송사·계약·요율·운영 정책, 예외 비용과 사고 처리 승인 | 등록 정책·승인 결과를 참조하고 근거 데이터를 제공 |

TMS는 모든 영역을 직접 호출한다고 가정하지 않는다. 인터페이스 방식은 API 조회, 확정 사건 수신, 이벤트 전달 또는 배치 대사로 구성될 수 있다. 중요한 것은 호출 방식이 아니라 각 사실의 최종 소유자와 중복·실패 복구 규칙이다.

## 15.5 운송 기준정보·정책 변경의 책임

출발/도착 거점, 운송 구간, 차량 유형, 차량 적재 중량·부피, 온도 조건, 상하차 가능 시간, 등록 운송 수단 적합성 및 운영시간은 운송 계획의 기준정보다. 기준정보의 소유 시스템과 승인자는 프로젝트의 기준정보/BackOffice 정책에서 확정한다. TMS는 유효 버전의 기준정보를 참조해 계획을 검증하고, 정보가 미설정·만료·조회 불명인 경우 안전 한도를 임의로 넓히지 않는다.

운송사·계약·요율·예외 비용 승인, 사고 처리 승인과 운영 정책 승인 권한은 관련 BackOffice/관제/업무 책임자에게 둔다. TMS는 배정·운송 실적과 비용 근거를 제공하지만 승인되지 않은 비용이나 사고 처분을 자동 확정하지 않는다. 운송 기준정보를 변경한 경우 이미 진행 중인 운송의 원계획·적용 버전·최신 예상·실제 결과를 구분하여 감사 가능성을 유지한다.
