# 02-상품-가격-혜택 (11-15, 21-24)

## 11-15. 운영자가 할인 행사 예약
### MD
1. 행사 상품, 가격, 날짜, 시간(시작과 종료) 예약 및 승인 요청
2. 등록된 행사 내용 승인자 검토 후 승인 또는 반려
-> 승인 후, 고객 화면이 예약된 시간에 맞춰 반영되는지 확인

3. 행사 시간 외의 기존의 상품 가격, 주문 결제 정보 유지  
4. 행사 시간 내에는 행사 정보로 변경된 정보로 변경되서 적용
->  장바구니에서 담은 후 행사 시간이 지나면 변경된 가격으로 안내창


5. 위 행사 이력 조회 가능 (요청 일시/ 변경자 / 승인자 / 행사 내용 / 진행 상태 / 비고 ) 
-> 동일한 상품이지만 행사 조건에 따라 여러 가격 버전이 존재, 조회 가능해야함 (가격 버전 상품코드 필요, 판매가, 상태)
-> 수정 내용 이력 역시 조회
6.  재고와 행사 가격 분리 : 재고가 있어도 행사가 아님, 행사를 진행해도 수량 소진 시 구매x

7. 다수의 행사 중복 적용 시 기준 
- 적용 가능한 행사 중 가장 낮은 가격으로 자동선택
- 정책으로 정한 우선 순위에 따라 특정 행사만 적용 (예: 회원특가 우선)
-> 중복 적용이 되지 않도록 설계

8. 행사 종료로 인한 가격 변경 고지
- 장바구니 변경 시 즉시 알림
- 결제 직전 재확인

### 예외
1. 예약 승인 후 실제 게시 실패시, 고객 판매가격을 확인하고 재게시 및 판매 중지 결정, 상품 일시적으로 노출 중지
-> 이미 접수된 가격은 그대로 보존, 주문 후에 변경하지 않는다.
2. 시간 경계 오차 주의

## 21-24. 소비기한 마감 할인 및 품질 검토
### 운영자
#### 1. 소비기한 마감 임박 할인 행사
- 같은 상품이라도 소비기한이 다르면 할인 대상을 분류
- 총 재고 합 : 32개 -> L01 소비기한 26.10.19 12개 + L02 소비기한 26.10.20 20개 -> 12개만 할인 반영해서 앱에 표시
- 수령 시점(배송 완료 시, 매장 수령 시) 기준은 정책 검토

1.1 소비기한 정보 제공 방식 비교
- 소비기한을 명시
- 정확한 날짜 대신 수령 시점을 기준으로 충분한 잔여 기간을 보장하는 방식
  
1.2 마감 소진 후 대안 비교
- 할인 재고 소진하면 품절로 안내
- 정상가 상품을 대안으로 제시, 고객이 동의한 경우에만 구매

#### 2. 출고 작업 중 풀질 이상 발견
- 판매 전 품질 점검
- 품일 이상 발견 시, 즉시 판매 보류
- 신규 구매 차단
- 이미 접수된 주문은 운영자가 별도로 확인
  
2.1 품질 이상 상품 판매 차단
- 이미 주문한 경우, 접수된 주문 취소 가능 + 취소 되었다는 안내
- 취소 후 대체 상품 제안, 고객이 동의한 경우에만 구매

#### 3. 마감 할인 상품 동시 구매 요청 처리
- 1 명만 확정, 다른 고객 품절 안내 -> 누가 결제 가능하게 할지 기준 필요

#### 4. 동일 상품의 입고 시점이 달라 수량과 가격이 다를 수 있음
- 고객 화면에 직접 표시할 지, 내부에서 관리할지는 운영 정책에 따라 결정
- 고객이 선택할 수 있게 함
- 작업자는 상품 바코드를 통해 로트 확인 및 수량 처리
- 각 로트 별로 총 수량, 예약, 판매 가능량을 실시간으로 관리
