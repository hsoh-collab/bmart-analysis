# 04-주문-결제-환불

## 주문 변경·취소 및 확정 이력 관리

### 1. 기능 목적

고객의 주문 변경 및 취소 요청을 주문과 배송 상태에 따라 처리한다. 변경 가능 여부, 추가 비용 발생 여부, 출고 및 기사 인계와의 경합을 검증하며, 변경이 확정된 주문 정보와 이전 이력을 관리한다.

### 2. 기본 비즈니스 로직

#### 2-1. 주문 변경 및 취소 요청

1. 고객은 주문 상세에서 변경 또는 취소할 항목을 선택한다.
2. 서버는 주문 상태와 배송 진행 상태를 확인한다.
3. 요청 유형과 주문 상태에 따라 직접 변경, 승인 요청, 취소 처리 또는 요청 거절로 분기한다.
4. 취소 요청이 별도의 확인 절차를 거치는 경우, 요청 접수와 취소 확정을 구분하여 관리한다.
5. 요청이 접수되면 요청 번호, 요청 유형, 요청 시각, 변경 전후 정보 및 처리 결과를 기록한다.

#### 2-2. 배송지 변경

1. 고객이 새로운 배송지를 입력하면 서버는 해당 주소의 서비스 가능 여부를 확인한다.
2. 배송 불가 지역이면 변경을 거절하고 기존 배송지를 유지한다.
3. 배송 가능 지역이면 변경 전후의 상품 금액과 배송비를 비교한다.
4. 추가 비용이 발생하면 고객에게 변경된 금액을 안내하고 동의를 받는다.
5. 추가 결제가 필요한 경우 결제 성공 여부를 확인한다.
6. 필요한 결제와 승인 절차가 완료되면 변경된 배송지를 확정한다.
7. 고객 동의가 없거나 추가 결제에 실패하면 변경을 확정하지 않고 기존 주문 정보를 유지한다.
8. 상품 준비 이후에는 운영 정책에 따라 지원담당자의 승인을 거쳐 변경한다.
9. 기사 인계 이후에는 일반적인 즉시 변경을 제한하고 고객센터를 통한 후속 처리를 안내한다.

#### 2-3. 주문 취소

1. 고객이 취소를 요청하면 서버는 현재 주문 및 배송 상태를 확인한다.
2. 취소 가능한 상태이면 취소 절차를 진행한다.
3. 취소 요청에 별도 검토가 필요한 경우 요청 접수 상태로 기록하고 처리 결과를 안내한다.
4. 전체 주문 취소가 확정되면 출고 작업자 PDA 및 관련 작업 시스템에 취소 상태를 반영한다.
5. 이미 취소된 주문은 기사에게 인계할 수 없도록 제한한다.
6. 기사 인계가 완료된 주문은 즉시 취소를 제한하고 반품·환불 또는 고객센터 지원 절차로 안내한다.
7. 취소 확정 여부에 따라 주문 및 배송 상태를 갱신하고 처리 이력을 기록한다.

### 3. 주문 변경 금액 검증

1. 변경 전 주문 금액과 변경 후 예상 금액을 계산한다.
2. 상품 금액, 배송비, 할인쿠폰 및 무료배송 조건을 확인한다.
3. 변경으로 인해 추가 비용이 발생하면 고객에게 최종 금액과 추가 결제 금액을 안내한다.
4. 고객이 변경 내용에 동의하고 필요한 추가 결제가 완료된 경우에만 변경을 확정한다.
5. 추가 결제에 실패하면 변경 요청을 실패 처리하고 기존 주문 금액과 배송지 등 확정 정보를 유지한다.
6. 취소 시에는 쿠폰 사용 및 배송비 할인 조건을 반영하여 환불 금액을 계산한다.

### 4. 주문 변경 버전 및 이력 관리

1. 최초 주문 정보를 첫 번째 버전(v1)으로 관리한다.
2. 고객이 변경을 요청하면 변경 예정 정보를 기존 주문과 구분하여 관리한다.
3. 서비스 지역, 금액, 추가 결제 및 필요한 승인 절차를 검증한다.
4. 변경 조건이 충족되면 변경 내용을 확정하고 현재 주문 버전을 갱신한다.
5. 변경 전 주문 정보는 이력으로 보존하며, 현재 주문 정보와 구분한다.
6. 변경 요청 및 승인·거절 내역에는 주문번호, 요청번호, 처리 시각, 변경 항목, 변경 전후 값, 처리자 및 결과를 기록한다.
7. 배송용 라벨과 봉투 등 출고 관련 정보는 확정된 최신 주문 버전을 기준으로 생성한다.
8. 변경이 거절되거나 실패한 경우 기존 확정 버전을 유지한다.

### 5. 주문 변경과 기사 인계의 경합 처리

취소 요청과 기사 인계가 동시에 발생하면 두 작업이 모두 성공하지 않도록 처리한다.

1. 취소가 먼저 확정되면 기사 인계를 차단한다.
2. 기사 인계가 먼저 확정되면 즉시 취소를 제한하고 후속 처리 절차로 안내한다.
3. 두 요청이 동시에 들어오면 서버에서 먼저 확정된 상태를 기준으로 나머지 요청의 처리 가능 여부를 검증한다.
4. 상태 변경 시 주문 상태를 다시 확인하여 이미 확정된 작업과 충돌하지 않도록 한다.
5. 최종 처리 결과와 처리 시각을 기록한다.

### 6. 예약 배송 시간 변경

1. 예약 배송 시간 변경은 별도 정책 검토 대상으로 분리한다.
2. 기능 도입 시 변경 허용 기한과 기존 예약 슬롯의 반환 규칙을 정의한다.
3. 변경할 시간대의 잔여 슬롯을 확인하고 확보할 수 있는 경우에만 변경을 확정한다.
4. 현재 제공 여부와 구체적인 운영 정책은 확정되지 않았으므로 기본 주문 변경 기능과 구분한다.

### 7. 운영자 관리 및 검증

- 운영자는 주문 상세, 변경 이력, 취소 요청 및 처리 로그를 확인할 수 있어야 한다.
- 주문 변경 요청의 승인·거절 결과와 변경 전후 정보를 조회할 수 있어야 한다.
- 배송 불가 주소, 추가 결제 실패, 출고 완료 등 변경 불가 사유를 기록한다.
- 출고 작업자 PDA와 주문 관리 시스템 간 주문 상태가 일치하도록 관리한다.
- 동일 주문에 대한 변경·취소 요청이 중복되거나 동시에 처리되는 경우 확정 상태가 충돌하지 않도록 검증한다.

### 8. 핵심 검증 시나리오

| 시나리오 | 기대 결과 |
|---|---|
| 배송 가능 주소로 변경 | 조건 검증 후 변경을 확정한다. |
| 배송 불가 주소로 변경 | 요청을 거절하고 기존 주소를 유지한다. |
| 배송지 변경으로 추가 비용 발생 | 고객 동의 및 필요한 추가 결제 후 변경한다. |
| 추가 결제 실패 | 변경을 확정하지 않고 기존 주문을 유지한다. |
| 상품 준비 이후 주소 변경 | 운영 정책에 따른 승인 절차를 적용한다. |
| 기사 인계 이후 취소 요청 | 즉시 취소를 제한하고 후속 지원을 안내한다. |
| 취소 확정 후 기사 인계 시도 | 인계를 차단한다. |
| 기사 인계 확정 후 취소 요청 | 즉시 취소를 제한한다. |
| 주문 변경 승인 | 최신 버전을 현재 주문으로 적용하고 이전 버전을 보존한다. |
| 주문 변경 거절 | 기존 확정 버전을 유지한다. |
| 예약 배송 시간 변경 | 정책 확정 전에는 기본 기능과 분리하여 관리한다. |
