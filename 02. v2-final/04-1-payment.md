# 04-주문-결제-환불

## 주문 결제 시도 및 승인 기록

### 1. 기능 목적

고객이 주문서에서 결제 수단을 선택하고 외부 PG(Payment Gateway)를 통해 결제를 진행하면, 서버가 결제 승인 결과를 확인하여 주문 상태에 반영한다.

외부 결제 앱의 종료, 네트워크 오류, 응답 유실 등의 상황에서도 중복 결제가 발생하지 않도록 기존 결제 거래를 조회하고 관리한다.

### 2. 관련 주체

- **고객:** 결제 수단 선택, 외부 인증 및 결제 진행, 결제 결과 확인
- **마트 앱:** 주문 정보 임시 유지, 외부 결제 화면 연결, 결제 결과 표시
- **회사 서버:** 결제 요청 관리, PG 승인 요청, 승인 결과 확인, 주문 상태 갱신
- **PG사:** 결제 인증 및 승인 처리, 거래 식별 정보와 결제 결과 제공
- **운영자:** 주문 및 결제 거래 내역 확인, 결제 상태 모니터링

### 3. 기본 비즈니스 로직

#### 3-1. 결제 수단 선택 및 결제 요청

1. 고객은 주문서에서 카드 등 지원되는 결제 수단을 선택한다.
2. 마트 앱은 주문 정보와 결제에 필요한 정보를 바탕으로 서버에 결제를 요청한다.
3. 서버는 주문 정보, 결제 금액, 주문 상태 및 기존 결제 거래 여부를 확인한다.
4. 서버는 해당 결제 시도를 식별할 수 있는 결제 요청 키를 관리한다.
5. 동일한 결제 요청이 반복 전달되면 새로운 결제 거래를 무조건 생성하지 않고 기존 거래의 처리 상태와 결과를 확인한다.
6. 유효한 요청이면 서버는 PG 결제 절차를 시작하고, 필요한 경우 고객을 외부 결제 앱 또는 PG 인증 화면으로 연결한다.

#### 3-2. 외부 결제 인증 및 승인 처리

1. 고객은 외부 결제 앱 또는 PG 인증 화면에서 본인 인증 및 결제 절차를 진행한다.
2. 고객의 인증 결과는 PG사를 통해 전달된다.
3. 회사 서버는 PG사에 결제 승인 요청을 보내고 승인 결과를 확인한다.
4. 서버는 PG 거래 번호와 결제 요청 키 등을 이용해 해당 거래를 식별한다.
5. 승인 결과가 확인되면 결제 거래 상태를 승인 완료로 갱신한다.
6. 서버는 승인된 결제 거래와 주문을 연결하고 주문 완료 처리를 진행한다.
7. 마트 앱은 서버에서 확인된 주문 및 결제 상태를 바탕으로 고객에게 결과를 표시한다.

※ 고객의 외부 인증 완료와 실제 결제 승인은 구분한다. 외부 인증을 완료했더라도 서버가 승인 결과를 확인하기 전에는 주문을 결제 완료로 확정하지 않는다.

#### 3-3. 결제 결과 확인 및 주문 확정

1. 서버는 PG사의 응답 또는 거래 조회 결과를 통해 결제 승인 여부를 확인한다.
2. 결제 승인이 확인되면 해당 주문을 결제 완료 상태로 변경한다.
3. PG 응답이 지연되거나 결과를 확인할 수 없는 경우에는 결제 결과 확인 중 상태를 유지한다.
4. 결과가 불명확한 상태에서는 결제 실패로 단정하거나 새로운 결제를 즉시 요청하지 않는다.
5. 기존 결제 요청 키 또는 PG 거래 식별 정보를 이용해 거래 결과를 재조회한다.
6. 조회 결과 승인 완료로 확인되면 기존 거래를 기준으로 주문을 확정한다.
7. 실패가 명확하게 확인된 경우에는 정책에 따라 고객에게 결제 재시도를 안내한다.

### 4. 예외 상황별 처리 로직

#### 4-1. 외부 결제 앱에서 결제를 취소한 경우

1. 고객이 외부 결제 앱에서 결제를 취소한다.
2. 고객이 마트 앱으로 복귀하면 서버 또는 PG 조회를 통해 기존 거래 상태를 확인한다.
3. 결제 실패 또는 취소가 확인되면 주문은 결제 완료 처리하지 않는다.
4. 고객은 주문서 또는 결제 수단 선택 화면으로 돌아갈 수 있다.
5. 장바구니와 입력한 배송 주소 등 주문 작성 정보는 유지한다.
6. 고객이 다시 결제하려는 경우 기존 거래의 최종 상태를 확인한 뒤 새로운 결제 시도를 허용한다.

#### 4-2. 외부 결제 앱 종료 또는 네트워크 오류가 발생한 경우

1. 외부 결제 앱이 종료되거나 네트워크 문제로 결제 응답이 유실될 수 있다.
2. 마트 앱은 결제 결과 확인 화면을 표시한다.
3. 서버는 기존 결제 요청 키를 이용해 PG 거래 상태를 조회한다.
4. 조회 중에는 결과 확인 중 상태를 유지한다.
5. 승인 완료가 확인되면 기존 결제 거래를 주문과 연결하고 주문을 확정한다.
6. 결제 실패가 명확하게 확인되면 재시도할 수 있도록 안내한다.
7. 결과를 확정할 수 없으면 추가 조회를 진행하고, 확인 전까지 중복 결제를 방지한다.

#### 4-3. 결제 복귀 링크가 유실된 경우

1. 외부 결제 화면에서 마트 앱으로 돌아오는 링크가 유실될 수 있다.
2. 고객이 마트 앱을 다시 실행하면 기존 주문과 결제 거래를 확인할 수 있도록 한다.
3. 앱은 기존 거래 식별 정보를 바탕으로 서버에 결제 상태를 조회한다.
4. 서버는 PG사의 거래 결과를 확인하여 기존 주문에 반영한다.
5. 기존 거래가 승인 완료라면 새 결제를 진행하지 않고 해당 주문의 결과를 표시한다.

#### 4-4. 결제 결과 조회

**자동 조회**

1. 고객이 외부 결제 화면에서 앱으로 복귀하면 기존 거래의 결과를 자동으로 조회한다.
2. 승인 완료이면 주문 완료 화면으로 이동한다.
3. 실패가 확인되면 결제 재시도 안내를 표시한다.
4. 결과가 불명확하면 확인 중 상태를 유지한다.

**사용자 직접 조회**

1. 고객은 결제 결과 확인 화면 또는 주문 관련 화면에서 '결제 결과 조회'를 선택할 수 있다.
2. 서버는 기존 결제 요청 키 또는 PG 거래 식별 정보를 이용해 거래를 조회한다.
3. 조회 결과에 따라 주문 상태와 고객 화면을 갱신한다.

※ 자동 조회와 사용자 직접 조회는 모두 기존 거래의 상태를 확인하는 작업이며, 그 자체로 새로운 결제 요청을 생성하지 않는다.

### 5. 운영자 결제 관리 로직

1. 운영자는 결제 관리 화면에서 주문 정보와 결제 거래 내역을 확인할 수 있다.
2. 각 결제 거래는 해당 주문과 연결되어야 한다.
3. 운영자는 결제 요청 키, PG 거래 번호, 결제 상태 및 승인 결과를 확인할 수 있어야 한다.
4. 동일한 결제 요청 키로 요청이 반복되면 기존 거래의 처리 상태와 결과를 조회할 수 있어야 한다.
5. PG 응답 지연 시 거래를 확인 중 상태로 유지하고, 확인되지 않은 거래를 임의로 실패 처리하지 않는다.
6. 고객 앱에 승인 결과가 전달되지 않았더라도 서버가 기존 거래의 승인 사실을 확인하면 해당 주문에 승인 결과를 반영한다.
7. 운영자는 중복 거래, 승인 결과 미확인, 주문과 결제 상태 불일치 등의 상황을 확인할 수 있어야 한다.

### 6. 데이터 관리 및 제약 조건

- **결제 요청 키:** 동일한 결제 요청의 중복 처리를 방지하기 위한 식별 키로 관리한다.
- **PG 거래 번호:** PG사에서 발급한 거래 식별 정보를 저장하고 중복 등록을 방지한다.
- **주문 및 결제 연결:** 결제 거래는 대상 주문과 연결되어야 하며, 승인된 결제 금액과 주문 금액을 검증한다.
- **중복 승인 방지:** 동일한 결제 거래가 중복으로 승인 처리되거나 주문이 중복 확정되지 않도록 한다.
- **상태 관리:** 결제 대기, 승인 처리 중, 승인 완료, 실패, 취소, 결과 확인 중 등의 상태를 구분한다. 실제 상태값과 전이 규칙은 구현 단계에서 확정한다.
- **거래 이력:** 결제 요청 및 결과 확인 이력을 추적할 수 있도록 관리한다.
- **상태 변경 검증:** 이미 승인된 거래를 재조회했다고 해서 새로운 승인 거래를 생성하거나 주문을 중복 확정하지 않는다.

### 7. 가격 변동 및 재결제 정책

1. 결제 실패 후 고객이 재결제를 진행할 때는 상품 가격과 할인 조건이 변경되었는지 확인한다.
2. 기존 주문 금액과 현재 상품 가격이 다른 경우 어떤 금액을 적용할지 정책을 정의해야 한다.
3. 가격 변경 시 고객에게 변경된 금액을 안내하고 필요한 경우 재확인을 받는다.
4. 기존 거래의 승인 여부가 확인되지 않은 상태에서는 새로운 결제를 허용하지 않거나, 중복 결제를 방지할 수 있는 별도 검증 절차를 적용한다.

### 8. 추가 확인 사항

- 지원하는 결제 수단별 외부 앱 연결 및 인증 방식
- 고객 기기에 카드사 앱이 설치되어 있지 않은 경우의 대체 인증 또는 결제 진행 방식
- PG 승인 결과 조회 API 및 재조회 주기
- 승인 결과 미확인 거래의 최종 확인 및 고객 안내 정책
- 결제 실패 후 재결제 시 기존 주문 금액과 변경된 가격의 적용 기준
- 주문 1건에 여러 결제 시도가 발생한 경우의 거래 이력 관리 기준
- 결제 승인 후 주문 처리 실패 시 복구 및 대사 정책
- PG사 연동 및 실제 결제 테스트 환경 구성

### 9. 핵심 검증 시나리오

| 시나리오 | 기대 결과 |
|---|---|
| 정상 결제 승인 | 승인 결과를 확인하고 주문을 완료 처리한다. |
| 고객이 외부 결제 앱에서 취소 | 주문을 결제 완료 처리하지 않고 주문 작성 정보를 유지한다. |
| PG 응답 지연 | 결과 확인 중 상태를 유지하고 기존 거래를 조회한다. |
| 동일 요청이 반복 전달됨 | 기존 거래를 확인하고 중복 결제를 방지한다. |
| 승인 응답이 앱에 전달되지 않음 | 서버가 기존 거래를 조회해 승인 여부를 확인한다. |
| 복귀 링크 유실 | 앱 재실행 후 기존 거래를 조회해 주문 상태를 복구한다. |
| 실패 확인 후 재결제 | 기존 거래의 최종 상태를 확인하고 재결제를 진행한다. |
| 결제 결과 조회 버튼 선택 | 기존 거래를 조회하며 새로운 결제 거래를 생성하지 않는다. |
| 결제 후 상품 가격 변경 | 정해진 가격 적용 정책에 따라 금액을 검증하고 고객에게 안내한다. |
